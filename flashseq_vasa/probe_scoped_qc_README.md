# 探针靶向 rRNA 清除效果评估（probe-scoped QC）

## 为什么要改这个指标

上一版报的是 **21.4 % 的 read 是 rRNA**。那个数字衡量的是"这个文库里还有多少 rRNA"，
不是"你的 RNase H 反应做得怎么样"。两者不同，因为被测到的 rRNA 里有很大一部分
**从来就不是探针的靶标**：5'ETS / ITS1 / ITS2 / 3'ETS 这些 spacer 上没有互补探针，
反应做得再完美也不会少一条。拿它们去扣分，等于用别人的错误评价你的实验。

**改法**：in-silico 去除**完全不动** —— 依旧用 `unique_rRNA_mouse.v2.fa`（357 条，
含完整 47S）把所有 rRNA 种类一起清掉，因为下游 mapping 不关心这条 read 是不是探针
靶标，它只要不干扰比对。**只把 QC 的计分范围收窄**到探针能够作用的那部分序列。

于是有两个数字，各自回答不同的问题：

| 指标 | 值（16 细胞合并） | 回答的问题 |
|---|---|---|
| 全部 rRNA / 文库 | 19,258,892 / 90,137,383 = **21.37 %** | 这个文库的测序量有多少浪费在 rRNA 上（**产出**指标） |
| **探针靶区残留 / 文库** | 12,473,702 / 90,137,383 = **13.84 %** | **你的 RNase H 反应效果**（**实验**指标） |
| 非探针靶区 rRNA / 文库 | 6,785,190 / 90,137,383 = **7.53 %** | 与反应无关，是 rRNA 加工生物学的产物 |

**探针靶区残留占全部残留 rRNA 的 64.8 %。** 也就是说旧指标里有 35 % 的"扣分"
不该算在你头上。

## 一个必须先说清楚的前提：探针是按人设计的

你确认用的是 Adiconis 2013 Supplementary Table 6 那 195 条 50-mer 的反向互补。
那套探针是针对**人** rRNA 设计的（NR_003286 / NR_003287 / NR_003285 / V00589 /
NC_012920 的 12S、16S 区间），而你的样本是小鼠。所以"探针靶区"在小鼠上不等于
"整条成熟亚基"—— 探针只能结合序列仍然足够保守的那些窗口。

我用全局比对把人的探针模板投影到小鼠序列上，按 **50 nt 窗口 ≥90 % 一致性**
（即 ≤5 个错配，RNase H 仍可驱动切割）界定可结合区间：

**参考里的 357 条 contig 全部参与判定**：47S 上的核编码亚基用逐亚基全局比对投影；
其余 356 条（含 `Rn18s-rs5` 这条独立的 1,849 bp 18S 拷贝、2 条 5.8S 样拷贝、
2 条线粒体 rRNA、351 条 5S 家族拷贝）各自与 6 条人探针模板做局部比对，取得分最高者
作为其靶标归属，再在该 contig 坐标上划区间。

| 靶标 | 小鼠全长 (bp) | 可结合 (bp) | 覆盖率 |
|---|---|---|---|
| 18S（47S 内 + Rn18s-rs5） | 3,719 | 3,718 | **100 %** |
| 28S | 4,730 | 4,211 | 89.0 % |
| 5.8S（47S 内 + 2 条拷贝） | 448 | 344 | 76.8 % |
| 5S（351 条拷贝合计） | 39,534 | 14,313 | **36.2 %** |
| 线粒体 12S | 955 | 346 | **36.2 %** |
| 线粒体 16S | 1,582 | 452 | **28.6 %** |

**核编码 18S/28S 基本没问题，但线粒体 rRNA 和大多数 5S 假基因拷贝只有约 1/3 的序列
人鼠够保守。** 这不是你反应的问题，是探针选型的固有局限。因此评分只在上面这
23,384 bp 的可结合窗口内进行（区间文件 `probe_target_intervals.tsv`，173 个区间，
覆盖 157 条 contig）—— 探针本来就够不着的地方不计分。

## 结果

**逐细胞（完整表见 `probe_scoped_depletion_per_cell.csv`）**：探针靶区残留在
12 个深测细胞里高度一致，**11.8 %–16.4 %**（中位 13.8 %）；4 个浅测细胞
（<1 M reads）为 4.3 %–7.8 %，但这几个细胞总量太小，比例不可直接与深测细胞比较。
一致性本身是好消息 —— 说明反应在孔间是**可重复**的，不是随机失败。

**按靶标拆分（`probe_scoped_residual_by_species.csv`，按可结合长度归一化）**：

| 靶标 | 残留 reads | 占探针靶区残留 | 每 kb 可结合序列的残留 reads |
|---|---|---|---|
| 28S | 9,744,456 | 78.1 % | **2,314,048** |
| 18S | 2,092,300 | 16.8 % | 562,749 |
| 5.8S | 388,720 | 3.1 % | 1,130,000 |
| 线粒体 16S | 189,587 | 1.5 % | 419,440 |
| 线粒体 12S | 57,958 | 0.5 % | 167,509 |
| 5S | 681 | 0.01 % | **48** |

**关于密度的一个校正**：read 只要**接触**到区间就计数，所以对长度 L 的区间，
有效捕获宽度其实是 L + r − 1（r = 平均比对读长 76.6 nt）。区间越短，密度被高估得越多。
按 `(L+r−1)/L` 逐靶标校正后（`probe_scoped_residual_by_species.csv` 的
`reads_per_kb_corrected` 列）：28S 1,993,151、5.8S 681,955、18S 530,395、
线粒体 16S 279,627、线粒体 12S 89,148、5S 27。**校正前后排序不变**，28S 始终最高
（校正后领先 5.8S 2.9 倍，校正前 2.1 倍），所以下面的结论不依赖这个边缘效应。

按密度看（最后一列才是公平比较，因为靶标长度相差近 100 倍）：

- **5S 被清得极其干净** —— 48 reads/kb，比 28S 低约 4.8 万倍。这是探针体系
  能work的**阳性对照**：同一批探针、同一个反应，5S 几乎归零。
- **28S 密度最高（2.31 M reads/kb），且贡献了 78.1 % 的绝对残留量**。它既是最长的
  靶标，又有 11 % 的序列人鼠差异过大够不着 —— 要提升总体效果，**28S 是唯一值得
  优先投入的方向**。
- **5.8S 密度次高（1.13 M reads/kb）**。它在 47S 内只有 157 bp，相当于只有 3 个探针
  窗口，一旦这几条探针效率不佳就没有冗余补偿。

## 判读建议

5S 的结果证明杂交、RNase H 消化、DNase 清除这几步在化学上是成立的，所以
13.84 % 的残留不是"反应没发生"，更可能是**探针摩尔量相对底物不足**，或者
28S/5.8S 上若干条人源探针在小鼠上效率偏低。两条可检验的下一步：

1. **提高探针:RNA 摩尔比**（原方案是 1,000 ng probe : 1,000 ng RNA）。如果残留
   随投入量下降，就是量的问题。
2. **针对小鼠重新设计 28S 与 5.8S 的探针**，尤其是我标出的那 519 bp 人鼠一致性
   <90 % 的 28S 区段。

**注意**：没有未处理对照文库，所以这里只能报**残留负担**（残留占文库比例），
无法给出真实的耗竭倍数（fold-depletion）。要拿到后者，需要一个跳过 RNase H
步骤、其余处理相同的对照孔。跨批次比较这个百分比时要留意输入 RNA 量和测序深度
差异 —— 这也是为什么上面 4 个浅测细胞不能与深测细胞并列解读。

## 文库结构核对

按你给的新结构（R1 = 21 nt RA5 + 12 nt UMI/barcode + polyA；R2 = 21 nt RA3 + cDNA）
核对了 SnapGene 图与 `config.sh`，一致：

- R1 前 21 nt = `GAGTTCTACAGTCCGACGATC`，确认为 RA5 接头的 3' 末端（`SKIP5=21`）
- R2 前 21 nt = `CCTTGGCACCCGAGAATTCCA`，确认为 RA3（`TGGAATTCTCGGGTGCCAAGG`）的反向互补
- 12 nt = `LEN_UMI=6` + `LEN_CBC=6`，`UMI_FIRST=yes`；其后为 polyT
- `BC_READ=R1` / `BIO_READ=R2`

**关于 `STRANDED`**：上一轮我实测到 15–21 % 的 rRNA 比对是反向的。按现在这个结构，
R2 = RA3 + cDNA，`STRANDED=y` 的设置与 read2 的方向约定是自洽的，那部分反向比对
更可能是真实的 antisense 转录本或 IVT 产生的反向产物，不应当作 rRNA 丢弃 ——
现有行为（放行给 STAR）是合理的。但 `code/flashseq_vasa/config.sh` 里
`FSV_STRANDED="n"` 与 `own_version` 的 `STRANDED="y"` 仍然不一致，
**两条路径产出的 count table 不能混用**，建议你确认哪条是主线。

## 复现

```bash
# 1. 生成探针可结合区间（本地，需要 biopython；会联网取 NCBI 序列）
#    输出 probe_target_intervals.tsv
# 2. 在 nemo 上评分
sbatch --partition=ncpu --account=u_turnerj -c 4 --mem=16G --time=02:00:00 \
       --wrap="bash probe_scoped_qc.sh"
```

`probe_scoped_qc.sh` 全部中间文件写在作业目录（scratch），**不向 working 写任何东西**。

**序列核对**：`unique_rRNA_mouse.v2.fa` 中的 47S contig 与 NCBI BK000964.3:1-13403
逐碱基完全一致；`mt-Rnr1`(955 bp)、`mt-Rnr2`(1582 bp) 与 NC_005089.1 对应区间完全一致
（均于 2026-08-02 核对）。参考中的 5S 家族拷贝无一与 NR_030686.1 完全相同（长度 117–121 bp
不等），故所有非 47S contig 的可结合区间均由逐条局部比对得出；357 条中有 157 条产生了区间。

**计数口径**：每条 BAM 记录计一次，跳过 secondary/supplementary（flag 0x100/0x800）。
一条 read 若与多个探针区间重叠，归给重叠最长的那个。54.4 % 的探针靶区 read 完整落在
某个区间内，其余跨越区间边缘。

**修订记录（2026-08-02）**：初版的区间只建在 47S、2 条线粒体和 5S 拷贝上，漏掉了
`ENSMUSG00000119584_Rn18s-rs5`（1,849 bp，独立的 18S 拷贝，100 % 可结合），
导致其约 0.95 M 条 read 被错误归入 off-probe。现已改为对全部 357 条 contig 逐条
判定靶标归属。受影响的数字：探针靶区残留 12.79 % → **13.84 %**，占残留 rRNA 比例
59.9 % → **64.8 %**。结论方向不变（5S 干净、28S 是瓶颈），但 18S 的绝对残留量
上修了一倍（1.15 M → 2.09 M）。
