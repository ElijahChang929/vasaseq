==============================================================================
distinct values in _total.UFICounts : [np.int64(0), np.int64(1)]
CONFIRMED: UFICounts holds only 0/1 -- a DETECTION MASK, not a
molecule count. One literal UMI key "A" per gene per column.
TranscriptCounts == UFICounts elementwise : True
CONFIRMED: bc2trans at K = 4**len("A") = 4 maps 1 -> 1.0 exactly, so
the TranscriptCounts tables ARE the mask. Neither carries abundance
information. ReadCounts is the quantification; carry only that.
sum(UFI) - count(reads>0) = 0   (0 confirms UFI is exactly the mask)

NO UMI CEILING EXISTS ON THIS PATH. bc2trans clamps at x >= K; K = 4
here, and UFI per gene per column is at most 1, so the clamp is
unreachable. VASA dropped 8 genes at its K = 4096 ceiling; that filter
has no analogue here and must not be carried over.

ASYMMETRY WORTH STATING when these rows are compared with the VASA side:
the FLASH-seq rows above are clean of one specific artefact that the VASA
rows are not. FLASH-seq runs stranded=n, so an antisense ribosomal read is
caught by step 3 on its own side. VASA runs stranded=y (correctly, for a
stranded protocol), and this library is measurably less strand-specific
than the published one -- 57.7-83.8% of its ribosomal reads are forward,
median 74.8%, against 92.7-97.4% published (measured on both plates with
riboread-selection.py's own two predicates). So ~24% of VASA ribosomal
reads are sent to the non-ribosomal arm and go on to be gene-assigned;
vasaplate_check/README.md documents that failure mode inflating one
antisense rRNA locus ~600x. Treat any rRNA / MiscRna / MtRrna row on the
VASA side as possibly carrying antisense rRNA leakage rather than as a
clean measurement. It does not affect the FLASH-seq rows above.
